# 题目 03 业务规则检查

## 用途

对本仓库（网校作业平台）的 Go 实现做**规则级**核查，把题面每一条业务约束映射到可观察的代码行为或接口响应，输出可定位到文件的缺口清单。不评价代码风格，不替代单元测试。

## 触发场景

- 完成某个业务任务（发布/提交/批阅/补交/积分/汇总）后自查。
- 出现疑似缺陷：重复发奖、版本号跳号、旧请求覆盖新内容、批了旧版却置为通过、他人作业可见。
- PR 前的业务门禁检查。
- 验收阶段作为业务专项证据。

## 输入

1. 需求基线：`deliverables/01-需求分析/需求说明.md`（FR/AC）与 `业务流程与状态说明.md`（状态机）。
2. 代码：`internal/service/`、`internal/store/`、`migrations/`、`internal/handler/`。
3. 测试与输出：`go test ./... -coverprofile`、`go test -race` 原始日志（如有）。
4. 可选：运行中的服务地址，用于接口级验证。

缺失任一项时，在输出中标注"无法判定"及原因，不得推测通过。

## 执行步骤

逐项核查（详细判定标准与常见错误见 `references/business-rules.md`）：

1. **发布快照**：发布是否写入不可变快照；发布后修改要求是否返回 409 且不改动快照。
2. **可见性**：作业查询是否强制班级过滤；外班学生是否 404 而非 403 泄露存在性。
3. **版本链**：每次内容变更是否新增版本且保留历史；被拒绝的请求是否不占用版本号。
4. **幂等**：`request_id` 是否有唯一约束；同号同内容是否返回首次版本；同号异内容是否 409。
5. **旧请求**：更新是否校验 `base_version`；落后版本是否 409 且不覆盖。
6. **截止判定**：是否使用注入时钟；是否按人计算有效截止（含补交）；补交是否只影响该生。
7. **批阅绑定版本**：批阅入参是否含 `version_id`；非当前版本是否 409；退回反馈是否强制非空。
8. **批阅并发**：状态行是否有乐观锁（version 字段/CAS 条件更新）；并发更新与批阅是否有确定结果。
9. **积分幂等**：发奖是否与通过同事务；是否有唯一约束（student+assignment+reason）；重复通过是否不加分。
10. **权限**：身份是否只来自会话；助教批阅/设补交是否服务端 403；学生是否只能读自己数据。
11. **汇总追溯**：汇总是否含四类计数、最终状态、奖励流水、时间线；时间线是否覆盖首次提交→最终结果。

核查方式：优先读代码定位约束（SQL 唯一索引、WHERE 条件、事务边界），其次跑接口或测试验证行为。**只读代码不下结论**，每条结论需给出文件:行号或命令输出。

## 输出格式

```
## 业务规则核查（提交 <hash>，时间 <t>）

| # | 检查项 | 结论 | 证据（文件:行 / 命令输出） | 缺口与修复建议 |
|---|--------|------|------------------------------|----------------|
| 1 | 发布快照不可变 | 通过 | internal/service/assignment.go:88 ... | — |
| 4 | 幂等 | 不通过 | 仅内存 map，无唯一索引 | 增加唯一索引 + 哈希比对 |
...

### 阻断项（必须修复才能提交）
- ...

### 无法判定项
- ...（缺什么输入）
```

结论只允许：通过 / 不通过 / 无法判定。不得出现"基本通过"。

## 失败处理

- 代码或迁移缺失：标注"无法判定"，列出需要的文件，不猜测。
- 行为与文档不一致：以题面原文为准，同时指出文档需修订的位置。
- 发现缺陷：给出最小复现（请求/命令 + 期望 vs 实际），移交开发 Agent 修复；修复后**重跑本 Skill 全量检查**，不得只复测单点。

## 完成标准

- 11 项全部有结论且每项有证据位置。
- 阻断项为 0，或已修复并附复测证据。
- 输出保存到 `deliverables/05-Agent测试/` 或 `06-Agent验收/`，并在 `调用记录.md` 登记调用时间与结果摘要。

# 题目 03 业务规则判定标准

每条含：题面要求 → 期望实现特征 → 常见错误 → 快速验证方式。

## 1. 发布快照不可变

- 题面：发布后不允许静默改变要求，需保留已发布内容。
- 期望：发布时写入独立快照行（标题/要求/截止/发布人/时间）；学生页面与批阅台读取快照；更新接口对 `PUBLISHED` 直接拒绝。
- 常见错误：直接改 `assignments` 表同一行；用"最后修改时间"覆盖快照；发布后仍允许编辑标题。
- 验证：发布 → 修改请求 → 期望 409 `assignment_locked`，快照字段与发布时逐字一致。

## 2. 可见性

- 题面：只有本班学生可见。
- 期望：查询带 `class_id = session.class_id`；外班访问返回 404（不确认存在性）。
- 常见错误：仅前端隐藏列表；用 403 暴露存在性；通过作业 id 直查不校验班级。
- 验证：以 X01 会话请求作业页与提交接口，期望 404；以本班学生请求他人作业详情，期望 403/404。

## 3. 版本链

- 题面：未进入批阅的作业可更新，每次更新保留版本。
- 期望：`submission_versions` 只追加；`version_no` 仅在内容真正变更且成功时 +1；`enrollments.current_version_id` 指向最新。
- 常见错误：更新覆盖同一条记录；版本号由前端传入；被 409 的请求也占号。
- 验证：提交 v1 → 更新 v2 → 历史列表 2 条；重放请求后仍 2 条。

## 4. 幂等

- 题面：重复请求不产生额外版本；相同请求编号不得携带不同内容。
- 期望：`request_id` 唯一索引（按学生+作业作用域）；同号同哈希返回首次结果；同号异哈希 409。
- 常见错误：只在内存去重（重启失效）；用内容哈希当幂等键（相同内容不同请求被误并）；先查后插无唯一约束（并发双写）。
- 验证：连续重放 3 次 → 版本仍 1 条；同号改内容 → 409。

## 5. 旧请求保护

- 题面：设备补传的旧请求可能晚于新版本到达。
- 期望：更新携带 `base_version`，服务端与当前版本比较，不等则 409 且不写入。
- 常见错误：无 base 校验（旧内容覆盖新内容）；只比较时间戳（时钟不可靠）。
- 验证：当前 v2，携带 base=1 → 409，正文仍为 v2。

## 6. 截止判定

- 题面：个人有效截止时间前可提交；原截止后不得直接提交；补交按人一次性。
- 期望：`clock.Now()` 统一来源；`effective_deadline = extension.deadline ?? assignment.deadline`；比较用服务端时间。
- 常见错误：用 `time.Now()` 硬编码；全局改截止（影响他人）；补交可重复设置。
- 验证：时钟 +1h → 逾期学生 409；批准补交后该生成功、他人仍 409；二次批准 → 409 `extension_exists`。

## 7. 批阅绑定版本

- 题面：按明确版本批阅；已被替代版本不能再通过；退回须有文字反馈。
- 期望：接口入参含 `version_id`；校验 `version_id == current_version_id` 且状态为待批阅；同一版本只允许一个结论；退回反馈非空。
- 常见错误：按学生批阅（隐式取最新）；允许批历史版本；空反馈退回。
- 验证：v2 存在时按 v1 通过 → 409 `stale_version`；退回空反馈 → 400/409。

## 8. 批阅并发

- 题面：并发修改和批阅必须有明确冲突结果。
- 期望：`UPDATE ... WHERE state_version = ?` 或事务内 `SELECT FOR UPDATE`；影响行数 0 即 409 并返回当前状态。
- 常见错误：先读后写无锁（丢失更新）；冲突时返回 500；批旧版成功且置为通过。
- 验证：`go test -race` 并发用例：一方成功、另一方 409，最终状态唯一。

## 9. 积分幂等

- 题面：首次通过发 10 分；重复批阅/重试不重复发奖；提交/退回/未完成不发。
- 期望：通过事务内写 `points_ledger`；唯一约束 `(student_id, assignment_id, reason)`；冲突视为已发奖；不实现扣回。
- 常见错误：先 `SELECT` 判存在再插（并发双写）；把发奖放在事务外；退回也发奖。
- 验证：重复通过 3 次 → 流水 1 条、总分 10。

## 10. 权限

- 题面：助教无权批阅；学生只能看自己；不能改请求中的用户编号越权。
- 期望：身份取会话；写接口校验角色 + 资源归属；助教批阅 403；学生跨人访问 403/404。
- 常见错误：信任 `user_id` 参数；靠前端隐藏按钮；助教可改补交。
- 验证：助教调用批阅接口 → 403；学生改 `student_id` 查他人 → 403/404。

## 11. 汇总与追溯

- 题面：补交结束后查询完成汇总、各生最终状态、奖励流水，可追溯首次提交到最终结果。
- 期望：只读查询；四类计数与最终状态来自同一份数据；时间线来自 `events` 表（或等价审计记录），含操作者、动作、目标版本。
- 常见错误：汇总用前端统计；时间线缺失退回/补交节点；把"已批补交未交"错算为已交。
- 验证：走完退回+重交+补交流程后，汇总条数与流水条数一致，时间线可复述全过程。

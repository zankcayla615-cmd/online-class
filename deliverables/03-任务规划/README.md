## 规划要点

1. **顺序按依赖而非按页面**：先数据模型与权限（D-02/D-03），再版本与幂等（D-05/D-06），最后批阅与发奖（D-07/D-08）。版本链是全部规则的地基。
2. **每个后端能力立刻接页面**（D-11 与 D-04~D-10 交叉），避免最后集中补 UI 挤压测试时间。
3. **失败路径先于成功路径**：每个任务的 DoD 都要求验证至少一条拒绝路径（409/403/404）。
4. **门禁前置**：覆盖率不达标不得进入缺陷复测之后的任务；修改业务代码必须重跑受影响检查。
5. **编号不臆造**：提交计划中的 `<REQ-xx>` / `<BUG-xx>` 为占位，必须先经 meegle 核验，核验输出留档。

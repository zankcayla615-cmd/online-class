## 5. 任务完成后的自检口径（防止"看起来做完了"）

- 每个 D 任务完成时必须留下：`git commit`（符合规范）+ 对应 `go test -run` 输出 + 页面操作截图或 curl 输出。
- "页面能点"不等于完成：必须验证**失败路径**（逾期的四种拒绝、版本冲突、重复请求、越权）。
- 覆盖率不达标不得进入 T-04 之后任何任务；修改业务代码后必须重跑受影响检查。
- 任何任务若需要超出题面的功能（如附件、评分制），记录到 `假设清单.md` 而不是直接实现。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| SQLite 写并发导致 `database is locked` | 并发演示失败 | WAL + `busy_timeout`；写操作放在短事务内；业务冲突由状态版本判定，不依赖数据库锁语义 |
| 教学时钟被误认为"改数据" | 验收质疑 | 页面与文档标注偏移来源；测试与演示同一套判定；演示视频中显式说明 |
| 幂等键设计遗漏（如按学生而非请求） | 重复版本/重复发奖 | request_id 唯一索引 + 内容哈希；补 ledger 唯一约束兜底，测试覆盖重放 3 次 |
| 覆盖率注水（只测 happy path） | 门禁不通过 | T-01 先写失败路径用例清单（逾期/冲突/越权/重复），按清单补测 |
| CI 无 runner 或权限不足 | 部署卡住 | P-01 阶段确认；备用方案为本机 GitHub Actions runner 或教师指定环境，提前在 AGENTS.md 记录变更 |
| 页面耗时挤压测试时间 | 测试不足 | D-11 采用最简表单；每后端能力完成即接页面；预留 20 min 缓冲 |

## 2. 接口

`POST /api/assignments/{id}/extensions`（仅本班教师）

```json
{ "student_id": "S03", "deadline_at": "2026-11-20T10:00:00Z", "reason": "生病住院，需要补交" }
```

- 成功 `201`，返回 `student_id`、`deadline_at`、`reason`、`granted_by`、`granted_at`。
- 错误码：`forbidden_role` 403（助教/学生）；`not_found` 404（作业/学生/跨班）；`not_published` 409；`not_enrolled` 409；`already_passed` 409；`extension_exists` 409；`extension_deadline_invalid` 400；`invalid_input` 400。

## 3. 判定顺序与语义

```
教师 → 作业同班/已发布 → 参数（student_id/原因长度/截止存在）
     → 学生存在且同班且是学生 → 在名单中 → 未通过
     → 截止必须晚于原截止 → 未设置过 → 写入（+事件）
```

- 补交**不改状态、不改版本号**，只给该生一条更晚的有效截止；提交时仍由 `effectiveDeadline` 逐个学生读取。
- 事件 `extension_granted` 与授权同事务写入，`detail` 带新截止与原因，直接服务 D-10 时间线的"补交批准"节点。
- 补交截止只校验"晚于原截止"（FR-06 原文），**未额外要求晚于当前时间**：教学时钟偏移来自环境变量，若再加 now 校验，演示时切换时钟会让合法数据变成非法。该取舍记入假设，演示时选未来时间。

## 5. 过程中发现并修正的问题

1. **权限矩阵用例再次过期**：`TestWriteEndpointRoleMatrix` 里"教师批准补交"仍断言 501，落地后空请求体先返回 400。改为断言 400 并注明完整用例在 `extensions_test.go`。
2. **"等于原截止"被误判为合法**：测试里先 `clk.Now().Add(-time.Hour)` 建作业、再算一次 `clk.Now().Add(-time.Hour)` 作为补交截止，两次调用差几微秒，导致 `deadline.After(snapshot)` 为真。改为**先固定基准时刻再建作业**，让"等于原截止"真正相等。
3. **冒烟脚本污染证据**：请求体用 `-Encoding ascii` 写入，中文原因变成 `?????`，长度校验恰好也被"问号"满足。改为 UTF-8（无 BOM）写请求体，并给控制台设置 `chcp 65001`，否则响应里的中文会以乱码形式进入记录。
4. **请求体与响应文件同名互相覆盖**：`BodyFile 'ext'` 与 `curl -o .tmp_d09_ext.json` 撞名，清理时报"文件不存在"。改为请求体统一 `.tmp_d09_b_*.json`、响应单独命名。

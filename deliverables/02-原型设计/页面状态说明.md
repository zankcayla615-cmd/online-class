# 页面状态说明（原型 v1.0）

原型文件：`prototype/index.html`（双击打开，无需服务；`app.css` / `app.js` 同目录）
形态：静态 HTML + 原生 JS 内存状态机，**仅用于需求确认与验收演示**，不是最终实现。
正式实现将改为 Go 服务端渲染页面 + 同一套服务端规则（页面结构可复用本原型）。

## 0. 全局框架

| 区域 | 内容 | 说明 |
| --- | --- | --- |
| 顶栏左 | 03 标识 + 产品名 | 明确为原型，避免误认为成品 |
| 顶栏中 | 教学时钟（当前时间 / 偏移）+「+1 小时 / +1 天 / 重置时钟」 | 演示逾期与补交，同一套判定规则，仅时间来源不同（AS-01） |
| 顶栏右 | 当前身份 + 身份切换下拉 + 重置演示 | 切换等价于重新登录，用于多角色演示 |
| 左侧导航 | 按角色显示：教师 3 项 / 助教 1 项 / 学生 1 项 | 学生看不到教师入口，助教看不到批阅入口 |
| 右下 | Toast 提示 | 成功绿色、失败红色（带 4xx 错误码）、信息灰色 |

## 1. 页面清单

| # | 页面 | 角色 | 正常态 | 异常态（原型可点出） |
| --- | --- | --- | --- | --- |

## 2. 状态徽标语义

| 徽标 | 含义 | 判定 |
| --- | --- | --- |
| 未提交（灰） | 尚未提交，且未过有效截止 | `NOT_SUBMITTED` 且 `now ≤ 有效截止` |
| 逾期未交（深灰） | 未提交且已过有效截止 | `NOT_SUBMITTED` 且 `now > 有效截止`（派生，不落库） |
| 待批阅（橙） | 当前版本已提交、未有批阅结论 | `SUBMITTED` |
| 已退回（红） | 有退回结论，可在截止前重交 | `RETURNED` 且未逾期 |
| 退回·已逾期（深灰） | 已退回但已超有效截止 | `RETURNED` 且已逾期 |
| 已通过（绿） | 终态，锁定，已发奖 | `PASSED` |

## 3. 错误码 → 触发方式 → 页面表现（演示对照）

| 错误码 | 触发方式（原型中怎么点） | 页面表现 | 对应验收 |
| --- | --- | --- | --- |
| `assignment_locked` | P1 发布后点「尝试修改已发布要求」 | 红色 Toast，快照不变 | AC-02 |
| `version_conflict` | P5「模拟旧请求」 | 红色 Toast，当前版本不变 | AC-08 |
| `idempotency_conflict` | P5「同请求号改内容」 | 红色 Toast，不新增版本 | AC-07 |
| （幂等重放成功） | P5「重放上一次请求」 | 绿色 Toast，版本号不变 | AC-06 |
| `stale_version` | P2 先「模拟学生抢先重交」，再按列出的旧版本通过 | 红色 Toast，学生不被置为通过 | AC-09 |
| `feedback_required` | P2 退回且反馈为空 | 红色 Toast | AC-10 |
| `already_passed` | P5 已通过后再提交 | 按钮禁用；接口层返回 409 | AC-12 |
| `deadline_exceeded` | 顶栏 +1 小时（截止设为 1 分钟）后提交 | 红色 Toast + 页面红色提示条 | AC-13 |
| `extension_exists` | P2 对同一学生第二次「批准补交」 | 红色 Toast | AC-14 |
| `reason_required` | P2 补交原因少于 5 字 | 红色 Toast | AC-14 |
| `review_conflict` | P2 对已通过学生再批不同结论 | 红色 Toast | AC-15 |
| （重复通过幂等） | P2「重复通过两次」 | 两次绿色 Toast，积分仍 10、流水仍 1 条 | AC-15 |
| `403 forbidden` | P4「尝试批阅（越权演示）」 | 红色 Toast | AC-17 |
| 404 | 以 X01 登录 | 404 视图，无作业信息 | AC-03 |

## 4. 推荐演示脚本（约 8 分钟）

1. **布置**（教师）：P1 把截止改为 1 分钟 → 发布 → 点「尝试修改已发布要求」演示 `assignment_locked`。
2. **正常完成**（学生 S01）：提交 → 教师 P2 按 v1 通过 → 学生页积分 +10 → 教师 P3 汇总「达标 1/5」。
3. **修改分支**（学生 S02）：提交 → 教师退回（填反馈）→ 学生看到反馈、重交 v2 → 教师通过 → 学生版本记录里 v1 保留退回意见 → 汇总奖励流水仍 2 条。
4. **幂等与并发**（学生 S01/S02 + 教师）：S01 已通过后点「重放」与「同请求号改内容」；教师对 S02 点「模拟学生抢先重交」后按旧版本通过 → `stale_version`。
5. **逾期分支**（学生 S03/S04）：S04 提交 → `deadline_exceeded`；S03 助教 P4 记录催交 → 教师 P2 批准 S03 补交（填原因）→ S03 提交并通过；S04 再试仍被拒。
6. **核查**（教师）：P3 查看每生最终状态、补交标注、奖励流水（3 条）、时间线（发布→提交→退回→重交→补交→通过）。
7. **越权**：P4 点「尝试批阅」→ 403；切换 X01 → 404。

## 5. 与正式实现的已知差异（必须对齐）

| 项 | 原型 | 正式实现 |
| --- | --- | --- |
| 数据 | 页面内存，刷新重置 | 数据库持久化，重启可查 |
| 鉴权 | 顶栏切换身份 | 服务端会话 + 角色中间件，越权 403 |
| 并发 | 单线程模拟「抢先重交」 | 事务 + 状态行乐观锁，真实并发测试（`-race`） |
| 时间 | 可快进的教学时钟 | 同一规则，时间来源可配置 |
| 幂等 | 内存 `last` 记录 | 幂等键（request_id + 内容哈希）落库唯一索引 |
| 助教可见性 | 不可见正文 | 服务端不下发正文（AS-07） |

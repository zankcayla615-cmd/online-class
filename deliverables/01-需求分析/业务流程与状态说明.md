# 题目 03 业务流程与状态说明

> 与《需求说明.md》配套。所有状态与时间均以服务端 UTC 判定，"当前时间"可来自教学时钟（AS-01）。

## 1. 数据主体

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `users` | id、姓名、角色、班级、口令哈希 | 预置 T01/A01/S01~S05/X01(P02) |
| `assignments` | id、班级、标题、状态、发布快照、截止时间 | 快照发布后只读 |
| `assignment_snapshots` | assignment_id、题目、要求、截止、发布人、发布时间 | 不可变，学生看到的就是它 |
| `enrollments` | assignment_id、student_id、state、state_version、current_version_id | 每人一行，并发控制锚点 |
| `submission_versions` | id、assignment_id、student_id、version_no、内容、内容哈希、request_id、创建时间 | 只追加 |
| `reviews` | id、version_id、结论、反馈、教师、时间、request_id | 只追加，一版本一结论 |
| `extensions` | assignment_id、student_id、新截止、原因、批准人、时间 | 唯一约束（assignment+student） |
| `points_ledger` | student_id、assignment_id、原因、分值、时间 | 唯一约束（student+assignment+reason） |
| `reminders` | assignment_id、student_id、助教、方式、摘要、时间 | 只追加 |
| `events` | 聚合类型/ID、事件类型、操作者、前后状态、时间、关联版本 | 追溯时间线的唯一来源 |

## 2. 作业（Assignment）状态

```
        ┌─────────┐  发布(生成快照)   ┌────────────┐
        │  DRAFT  │ ───────────────► │ PUBLISHED  │
        └─────────┘                   └────────────┘
             │ 删除(仅草稿)                  │ 只读，不可改快照
             ▼                              ▼
          (不存在)                   "已结束"=派生（有效截止已过，仅影响汇总标注）
```

- 只有 `DRAFT` 可编辑/删除；`PUBLISHED` 的任何内容变更请求 → 409 `assignment_locked`。
- "已结束"不作为存储状态，避免"静默改变要求"和状态漂移；汇总页用 `now > 有效截止` 派生出结束标注。

## 3. 学生-作业（Enrollment）状态机

```
                   提交v1(now≤有效截止)
   NOT_SUBMITTED ──────────────────────► SUBMITTED
        │  逾期派生：now>有效截止            │  │
        │  → 展示"逾期未交"(非存储态)        │  │
        │                                   │  │ 更新(新版本)
        │                                   │  └──────┐
        │                                   │         ▼
        │                          通过(指定当前版本)  SUBMITTED(版本+1)
        │                                   ▼
        │                                PASSED (终态)
        │
        │        退回(指定当前版本,反馈必填)
        └────────◄──────── SUBMITTED ──────► RETURNED
                                            │  重交(now≤有效截止)
                                            └──────────► SUBMITTED(版本+1)

   PASSED：禁止提交、禁止更新、禁止再批阅改结论（重放幂等，不重复发奖）
```

转移合法性表：

| 从 | 事件 | 到 | 前置校验 | 违反时 |
| --- | --- | --- | --- | --- |
| NOT_SUBMITTED | 提交 v1 | SUBMITTED | now ≤ 有效截止；本班 | 409 `deadline_exceeded` / 403 |
| SUBMITTED | 更新 | SUBMITTED(v+1) | 当前版本未批阅；base_version 匹配；now ≤ 有效截止 | 409 `stale_version`/`version_conflict`/`deadline_exceeded` |
| SUBMITTED | 通过 | PASSED | 目标版本=当前版本；`review` 无记录 | 409 `stale_version`/`review_conflict` |
| SUBMITTED | 退回 | RETURNED | 同上 + 反馈非空 | 400 / 409 |
| RETURNED | 重交 | SUBMITTED(v+1) | now ≤ 有效截止（含补交） | 409 `deadline_exceeded` |
| PASSED | 任意写 | PASSED | 拒绝 | 409 `already_passed` |
| 任意未通过 | 批准补交 | 状态不变，仅改有效截止 | 无既有 extension | 409 `extension_exists` |

## 4. 版本链与"当前版本"语义

```
S02: v1(提交 10:00) ──退回(反馈F1)──► v2(10:40) ──退回(F2)──► v3(11:10) ──通过──► 终态
      └ 历史可查：内容、时间、请求编号、对应批阅结论
```

规则：
1. `version_no` 只在**内容真正变化且写入成功**时 +1；重放请求不 +1。
2. 任何"批阅""更新"都必须携带版本锚点：批阅带 `version_id`，更新带 `base_version`。
3. 教师端展示"当前版本号 + 历史版本列表"，批阅按钮绑定具体版本号，避免"盲批"。
4. 学生端展示"我的当前版本 / 历史版本"，并标注每版对应的批阅结论。

## 5. 有效截止时间

```
有效截止(student) = extension.deadline（若已批准 且 extension.deadline > assignment.deadline）
                  否则 assignment.deadline
```

- 判定只用服务端时间，客户端不参与。
- 补交按人独立生效：S03 补交后，S04 的有效截止仍是原截止（AC-14）。
- 补交一次性：已存在 extension 再申请 → 409。
- 补交批准必须落原因（谁、何时、为什么），进时间线。

## 6. 批阅与积分时序（首次通过发奖）

```
教师通过(v3) ─┬─► reviews 插入(结论=pass)
              ├─► enrollments.state=PASSED, state_version+1
              └─► points_ledger 插入(+10, reason=first_pass)   ← 同一事务
                       │ 唯一约束(student, assignment, reason) 冲突则忽略并视为已发奖
                       ▼
                  学生页积分 +10，教师汇总奖励流水 1 条

重复通过(v3 again) → 命中"该版本已有结论" → 幂等返回首次结果，不插入 review、不 +10
```

失败与回滚：
- 三步在同一事务内，任一步失败整体回滚，不允许"已通过但没发奖"或"发了奖但状态没变"。
- 重试（网络超时后客户端重发）：靠 `request_id` + 唯一约束双重兜底。

## 7. 并发冲突矩阵（必须有明确结果）

| 并发场景 | 处理 | 结果 |
| --- | --- | --- |
| 学生更新 vs 教师批阅（同一版本） | 乐观锁 `state_version` | 先提交者生效；后者 409 `version_conflict`/`stale_version` + 当前版本信息 |
| 学生两次更新（不同 request_id，同一 base_version） | 同上 | 仅一个成功 +1 版；另一个 409，不产生分叉版本 |
| 同一请求重放（相同 request_id） | 幂等表 + 唯一索引 | 返回首次结果，版本号不变 |
| 教师重复点击通过 | reviews 唯一(version) + ledger 唯一 | 1 条 review、1 条 +10 |
| 两教师（演示为同一账号双开）同时批阅同版本不同结论 | reviews 唯一(version) | 一个成功，另一个 409 `review_conflict` |
| 教师设置补交 vs 学生最后时刻提交 | 事务内读取有效截止 | 提交结果以读取到的有效截止为准；补交提交后仅对后续请求生效，时间线记录先后 |

## 8. 页面与操作的业务对应

| 步骤 | 角色 | 页面动作 | 落库效果 |
| --- | --- | --- | --- |
| 布置 | 教师 | 建草稿 → 发布 | assignments + snapshot + event |
| 提交 | 学生 | 填写文本 → 提交 | submission_versions(v1) + enrollment(SUBMITTED) |
| 催交 | 助教 | 在看板选学生 → 记录沟通 | reminders + event |
| 批阅 | 教师 | 打开批阅台 → 指定版本 → 退回/通过+反馈 | reviews + enrollment 状态变更（通过则 +ledger） |
| 重交 | 学生 | 看反馈 → 改写 → 提交 | submission_versions(v+1) |
| 补交 | 教师 | 汇总/批阅台 → 为指定学生设补交+原因 | extensions + event |
| 核查 | 教师 | 汇总页 | 只读：四类计数、最终状态、奖励流水、时间线 |

## 9. 时间线（追溯）示例

汇总页单个学生的展开视图：

```
10:00 S02 提交 v1（request r-a1）        → 待批阅
10:20 T01 退回 v1：反馈"缺步骤推导"       → 已退回
10:40 S02 重交 v2（request r-b7）
10:55 T01 通过 v2                        → 已通过，+10 积分
11:00 A01 记录催交（此前状态：未交→已交）  → 仅记录，不改状态
```

字段：时间、操作者角色、动作、目标版本、结论/反馈、状态前后、关联请求编号与事件 ID。

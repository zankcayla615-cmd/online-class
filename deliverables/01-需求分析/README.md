核心设计口径（后续阶段不得偏离）：
1. 发布即快照，发布后内容锁死（409 `assignment_locked`）。
2. 提交按版本追加，更新带 `base_version` 乐观锁。
3. 批阅绑定 `version_id`，非当前版本 → 409 `stale_version`。
4. 发奖靠事务 + 唯一约束（student+assignment+reason），重复批阅/重试不重复发奖。
5. 补交按人一次性，原因必填，只影响该生。

## 验收要求（场景 §2）

题目 03 关键规则落点（逐条对应，验收时按此核对）：
- 草稿发布后要求不可静默变更，保留已发布内容
- 个人有效截止时间前可提交/更新；未进入批阅可改；每次更新留版本
- 相同请求编号不得携带不同内容；重复请求不产生额外版本
- 按明确版本批阅；已被替代版本不得通过；并发修改与批阅须有明确冲突结果
- 已通过作业不可修改；退回后可在有效截止时间前重交，旧版本与意见可查
- 原截止时间后不得直接提交；教师可为指定未通过学生设置**一次**更晚补交截止并记录原因
- 首次通过发 10 积分，重复批阅/重试不重复发奖；提交/退回/未完成不发奖；不实现撤销
- 助教可看分类统计并记录催交，不可代替批阅；学生仅可见自己的内容与积分
- 教师可查完成汇总、各生最终状态、奖励流水，可追溯首次提交→最终结果

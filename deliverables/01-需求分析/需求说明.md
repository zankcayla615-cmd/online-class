# 题目 03 需求说明

> 依据：《题目.doc》业务范围与规则、《场景.doc》共同要求。
> 版本：v1.0（需求分析阶段）｜编写：学生｜对应仓库分支：`dev/03`

## 1. 业务背景与问题

网校教师课后布置课下任务，学生通过学习终端提交，助教跟进未完成学生，教师批阅并决定是否达标，平台给达标学生发 10 积分。

现场痛点（题面第 2 段）：设备网络问题导致**重复提交**、补传的**旧请求晚于新版本到达**、教师**重复点击通过**、学生**退回后重交**、截止后**个别补交**。若系统只记录"最后一次点击结果"，就无法回答：当前作业是哪一版、谁获得了奖励、哪些学生仍需跟进。

**因此本系统的核心不是"提交按钮"，而是"可追溯的版本 + 明确的当前态 + 幂等的副作用"。**

## 2. 角色与权限矩阵

预置：1 个班级（P01）、1 名教师（T01）、1 名助教（A01）、5 名学生（S01~S05）、1 名外班学生（X01，属 P02）。

| 能力 | 教师 | 助教 | 本班学生 | 外班学生 |
| --- | --- | --- | --- | --- |
| 创建/发布作业 | ✅ | ❌ | ❌ | ❌ |
| 查看已发布作业要求 | ✅ | ✅ | ✅（本班） | ❌ |
| 提交/更新自己的作业 | ❌ | ❌ | ✅ 仅本人 | ❌ |
| 查看他人作业正文 | ✅（批阅需要） | ❌（见 AS-07） | ❌ | ❌ |
| 批阅（通过/退回+反馈） | ✅ | ❌ 403 | ❌ | ❌ |
| 批准个别补交 | ✅ | ❌ | ❌ | ❌ |
| 查看班级分类统计 | ✅ | ✅ | ❌ | ❌ |
| 记录催交 | ❌ | ✅ | ❌ | ❌ |
| 查看本人反馈与积分 | — | — | ✅ 仅本人 | ❌ |
| 查看班级汇总/奖励流水/时间线 | ✅ | 只读统计（无人均正文） | ❌ | ❌ |

**鉴权原则**：身份只从服务端会话（登录后下发的 Cookie/Session）解析，**任何请求体或 URL 中的用户编号都不作为授权依据**；越权请求返回 403，不存在的资源返回 404，二者不泄露他人数据是否存在。

## 3. 功能需求

### FR-01 身份与鉴权
预置账号可登录（账号+口令，口令哈希存储）；会话过期后需重新登录；所有写操作服务端二次校验角色、班级归属、资源归属。

### FR-02 作业创建与发布
- 教师可创建草稿，必填：题目、提交要求、截止时间（UTC 存储）。
- 草稿仅教师可见，可编辑、可删除。
- 点击发布时**生成发布快照**（题目、要求、截止时间、发布人、发布时间），此后该快照不可变更。
- 发布后修改要求的请求一律拒绝（409 `assignment_locked`），提示"已发布内容不可静默变更，如需变更请新建作业"。
- 发布后作业仅对**本班**学生、本班教师与助教可见；外班学生访问返回 404。

### FR-03 提交与版本
- 学生提交纯文本内容；作业只接收文本（长度上限 5000 字符，UTF-8）。
- 只有"当前版本未进入批阅"时可更新；每次成功的内容变更生成**新版本**，版本号自 1 递增。
- 每次更新保留历史版本（内容、提交时间、对应请求编号），历史版本不可删除、不可修改。
- **有效截止时间** = 作业截止时间；若该生已被批准补交，则取补交截止时间。超过有效截止时间的提交直接拒绝（409 `deadline_exceeded`），**不进入待批阅**。
- 已退回的作业可在有效截止时间内重交，退回时的反馈与旧版本仍可查询。
- 已通过的作业禁止任何修改（409 `already_passed`）。

### FR-04 提交幂等（重复请求与旧请求）
- 客户端每次提交动作携带唯一 `request_id`（UUID）。
- 相同 `request_id` + 相同内容：视为重放，返回**首次结果**（同一版本号），不新增版本、不改变任何状态。
- 相同 `request_id` + 不同内容：拒绝（409 `idempotency_conflict`），不写入，并提示"相同请求编号不得携带不同内容"。
- 内容比较前做规范化（去首尾空白、统一换行），避免因传输差异误判冲突。
- 补传的旧请求（不同 `request_id`、更早内容）到达时：按"更新"处理会覆盖新版本，因此**引入版本前置校验**——客户端更新时须携带其基于的 `base_version`；若该生当前版本已大于 `base_version`，返回 409 `version_conflict`，不写入，页面提示重新加载。禁止用旧内容静默覆盖新版本。

### FR-05 批阅（按明确版本）
- 教师批阅必须指定目标 `submission_version_id`，而不是"批阅这个学生"。
- 校验：目标版本必须等于该生当前版本且状态为待批阅（`SUBMITTED`），否则 409 `stale_version`（已被新版本替代 / 已批阅过）。
- 通过：学生状态 → `PASSED`，写反馈（可空）、批阅人与时间；同一事务内触发 FR-07 发奖。
- 退回：学生状态 → `RETURNED`，**反馈必填**（非空，≤500 字）。
- 重复批阅/重试（同一版本、同一结论）：幂等返回首次结果，不产生第二条批阅记录、不重复发奖；同一版本给出相反结论 → 409 `review_conflict`。
- 并发"学生更新"与"教师批阅"：以学生作业状态行版本号做乐观锁，先提交者生效，后者得到 409 `version_conflict`/`stale_version` 并返回当前版本信息，**不允许出现"批阅了旧版本却把学生标记为通过"**。

### FR-06 补交（一次性、按人）
- 教师可为**尚未通过**的指定学生设置一次更晚的补交截止时间，必须填写原因（≥5 字，≤200 字），并记录设置人与时间。
- 每个学生每份作业最多一次；重复设置返回 409 `extension_exists`。
- 补交截止必须晚于原截止时间；只影响该生，其他学生截止时间不变。
- 补交截止生效后，该生在补交时间内可提交/重交；仍未提交则汇总中显示"逾期未交（已批补交）"。

### FR-07 积分发放
- 学生作业**首次**通过时发放固定 10 积分，写入积分流水（学生、作业、原因 `first_pass`、分值、时间）。
- 以数据库唯一约束（学生+作业+原因）保证幂等：重复批阅、并发重试、失败重试均不重复发奖。
- 提交、退回、未完成、逾期均不发奖。
- 本题不实现撤销/扣回。

### FR-08 学生视图
- 学生只能看到：作业要求（发布快照）、本人当前版本与历史版本、本人反馈、本人积分与积分流水。
- 不得通过修改请求参数查看他人提交、他人反馈、他人积分。

### FR-09 助教看板与催交
- 助教可查看本班该作业的四类清单：未交、待批阅、退回、通过，含每生状态与最近时间。
- 助教可针对学生记录催交（时间、方式：站内/电话/群、沟通结果摘要），可多次追加，记录不可篡改。
- 助教**无批阅权**：调用批阅接口返回 403；不得代替教师设置补交。

### FR-10 班级汇总与追溯
- 教师（助教只读统计）可查询：完成率与四类计数、"各学生最终状态"、"奖励流水"、"完整时间线"。
- 每个学生可追溯：首次提交时间与版本 → 每次更新 → 每次批阅结论与反馈 → 补交批准 → 最终结果与发奖记录。
- 汇总为实时只读查询，不修改业务状态。

### FR-11 持久化与教学时钟
- 所有业务数据落数据库，服务重启后结果与时间线仍可查询。
- 支持可配置教学时钟（`TEACHING_CLOCK_OFFSET`，或对单个作业注入虚拟当前时间），用于在演示中缩短时长触发逾期/补交；**测试与线上演示使用同一套规则，仅"当前时间"来源不同**。

### FR-12 最小可操作页面
必须实现并真实可操作（非静态、非写死结果）：

| 页面 | 角色 | 关键操作 |
| --- | --- | --- |
| 登录页 | 全部 | 选择预置账号登录 |
| 作业编辑/发布页 | 教师 | 建草稿、发布、查看发布快照 |
| 批阅台 | 教师 | 指定版本通过/退回+反馈、批准补交（填原因） |
| 班级汇总页 | 教师/助教 | 四类计数、每生最终状态、奖励流水、时间线 |
| 助教看板 | 助教 | 分类清单、记录催交 |
| 学生作业页 | 学生 | 查看要求、提交、更新、看历史版本、看反馈、看积分 |

失败必须展示**可读原因**（逾期、已通过、版本冲突、重复请求、无权限），不得只返回 500。

## 4. 必须演示的三组场景（可验收入口）

1. **正常完成**：教师发布 → S01 提交 → 教师按版本通过 → S01 得 10 分 → 教师查看汇总（完成 1/5）。
2. **修改分支**：S02 提交 v1 → 退回（含反馈）→ S02 重交 v2 → 通过 → 旧版本 v1 与退回意见仍可查 → 奖励仅 1 条 10 分。
3. **逾期分支**：S03 未交 → 助教记录催交 → 教师仅批准 S03 补交（记原因）→ S03 提交并通过；S04/S05 逾期仍不能提交（409）。

附加异常演示（验收必查）：重复请求幂等、同请求号不同内容冲突、旧请求覆盖被拒、并发批阅与更新冲突、外班学生不可见、助教批阅 403、重复通过不重复发奖。

## 5. 可验证验收条件

| 编号 | 条件（输入 → 可观察结果） |
| --- | --- |
| AC-01 | 教师建草稿：仅教师可见，学生列表不出现 |
| AC-02 | 发布后修改要求 → 409，页面显示拒绝原因；发布快照内容与发布时一致 |
| AC-03 | 外班学生请求作业页/提交接口 → 404 / 403，不泄露作业存在 |
| AC-04 | S01 截止前提交 → 版本 v1，状态"待批阅"，教师端可见 |
| AC-05 | 未批阅时 S01 再次提交（新内容）→ 版本 v2，v1 仍在历史中 |
| AC-06 | 同 `request_id` 同内容重放 3 次 → 版本号不变，历史仍为 2 条 |
| AC-07 | 同 `request_id` 不同内容 → 409，不新增版本 |
| AC-08 | 携带已过期的 `base_version` 更新 → 409 `version_conflict`，当前版本内容不变 |
| AC-09 | 教师按 v1 批阅通过，但当前版本已是 v2 → 409 `stale_version`，学生不被置为通过 |
| AC-10 | 教师按 v2 退回且反馈为空 → 400；填写反馈后状态为"退回"，学生可见反馈 |
| AC-11 | S02 退回后重交 v3 → 通过；v1/v2 与两次反馈均可查询 |
| AC-12 | 已通过作业再提交 → 409 `already_passed` |
| AC-13 | 原截止后 S04 提交 → 409 `deadline_exceeded`，状态仍为逾期未交 |
| AC-14 | 教师为 S03 设补交并填原因 → S03 可提交；S04 仍被拒；S03 再次获补交 → 409 |
| AC-15 | S01 通过 → 积分流水 1 条 +10；教师重复点通过 3 次 → 流水仍 1 条，总分 10 |
| AC-16 | 并发：两请求同时通过同一版本 → 1 成功 1 幂等/409，奖励 1 条；并发更新与批阅 → 一方 409 且无脏状态 |
| AC-17 | 助教调用批阅/补交接口 → 403；记录催交后教师汇总可见该条 |
| AC-18 | 学生改请求参数查他人 → 403/404；学生页仅本人数据 |
| AC-19 | 重启服务后：版本、反馈、积分、时间线、催交记录均可查 |
| AC-20 | 教师汇总时间线完整呈现"首次提交 → 更新 → 批阅 → 补交 → 最终结果 → 发奖" |

## 6. 范围外（明确不做）

- 注册/找回密码、真实短信/邮件通知（用站内消息与页面提示代替）
- 附件上传、富文本、图片作业（本题仅文本）
- 通过后撤销/扣分、积分兑换与排行
- 多班级/多教师排课、跨班作业共享
- 微服务拆分、Redis/MQ（仅在确有需要时引入并说明理由）
- 第三方真实接入（如需要通知，采用可控 HTTP 模拟服务并标注为模拟）

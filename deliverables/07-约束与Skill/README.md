## 为什么在写代码前做这一步

场景 §3 要求约束文件在开发前编写并实际使用，§4 要求至少两个自编 Skill。先写约束再写代码，才能在后续会话中出现"Agent 越界被拦下"的真实记录；完工后补写无法通过过程核查。

## 两个 Skill 的分工

| Skill | 回答的问题 | 使用时机 | 输出 |
| --- | --- | --- | --- |
| `03-homework-business` | 业务规则做对了没有（版本/幂等/批阅/补交/发奖/权限） | 每个业务任务完成后、PR 前、验收时 | 11 项结论表 + 阻断项 + 证据位置 |
| `03-delivery-audit` | 整体能不能判通过（业务/权限/质量/过程/Git/部署/演示） | PR 前、上线前、缺陷修复后复验 | A~G 报告 + 阻断清单 + 复验范围 |
